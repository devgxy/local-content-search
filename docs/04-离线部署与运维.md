## 2. 一次性安装

### 2.1 创建虚拟环境

```bash
cd "/Users/example/Downloads/关键词检索"

# 使用 uv（推荐）
uv venv --python 3.11 .venv
source .venv/bin/activate

# 安装项目依赖（STEP-00 完成后）
uv pip install -e ".[dev]"
```

> 不要使用系统默认 `python3`：本机默认环境是 pydantic 1.10，LanceDB 需要 pydantic 2.7+。

### 2.2 安装关键依赖（等价手动命令）

```bash
uv pip install \
  "lancedb==0.40.0" \
  "pydantic>=2.7.4,<3" \
  "sentence-transformers==6.1.0" \
  "torch==2.14.1" \
  "transformers==5.20.2" \
  "sentencepiece==0.2.2" \
  "pymupdf==2.0" \
  "python-docx==1.2.0" \
  "python-pptx==1.0.2" \
  "ocrmac==1.0.1" \
  "pillow==13.0.0" \
  "charset-normalizer==3.5.2" \
  "fastapi==0.156.4" \
  "uvicorn[standard]==0.54.0" \
  "python-multipart"
```

**不要安装 `tantivy`**：LanceDB 0.40 已移除 Tantivy FTS，装了也不会用到。

### 2.3 下载模型（必须）

HuggingFace 直连在本机不可用，使用镜像：

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1

mkdir -p .models/bge-large-zh-v1.5 .models/bge-reranker-large
```

**向量模型文件清单：**

```text
.models/bge-large-zh-v1.5/
├── config.json
├── tokenizer_config.json
├── tokenizer.json
├── vocab.txt
├── special_tokens_map.json
├── sentence_bert_config.json
├── modules.json
├── 1_Pooling/config.json
└── pytorch_model.bin          # ~1.3GB
```

**重排模型文件清单：**

```text
.models/bge-reranker-large/
├── config.json
├── tokenizer_config.json
├── tokenizer.json
├── sentencepiece.bpe.model    # XLM-R 需要
├── special_tokens_map.json
└── pytorch_model.bin          # ~2.24GB
```

**下载示例：**

```bash
BASE=https://hf-mirror.com
for f in config.json tokenizer_config.json tokenizer.json vocab.txt \
         special_tokens_map.json sentence_bert_config.json modules.json \
         1_Pooling/config.json pytorch_model.bin; do
  curl -sSL --retry 3 -o ".models/bge-large-zh-v1.5/$f" \
    "$BASE/BAAI/bge-large-zh-v1.5/resolve/main/$f"
done

for f in config.json tokenizer_config.json tokenizer.json \
         sentencepiece.bpe.model special_tokens_map.json pytorch_model.bin; do
  curl -sSL --retry 3 -o ".models/bge-reranker-large/$f" \
    "$BASE/BAAI/bge-reranker-large/resolve/main/$f"
done
```

**校验：**

```bash
ls -lh .models/bge-large-zh-v1.5/pytorch_model.bin
ls -lh .models/bge-reranker-large/pytorch_model.bin
```

期望：前者 ≈1.3GB，后者 ≈2.24GB。若只有几十 MB，说明下载被截断。

**写完成标记：**

```bash
cat > .models/READY.json <<'JSON'
{
  "embed": "bge-large-zh-v1.5",
  "rerank": "bge-reranker-large",
  "dim": 1024,
  "verified_at": "2026-10-21"
}
JSON
```

### 2.4 可选：本地 Table Transformer

表格结构识别是**可选能力**，默认关闭：

```bash
python scripts/download_table_models.py
```

下载后目录：

```text
.models/table-transformer-detection/   # ~236MB
.models/table-transformer-structure/   # ~118MB
```

需额外安装：

```bash
timm==1.0.30
```

启用：

```bash
export TABLE_STRUCTURE_ENABLED=true
export TABLE_STRUCTURE_DEVICE=cpu
export TABLE_CELL_OCR=true
export TABLE_CONFIDENCE=0.5
export TABLE_TILE_DETECTION=true
```

相关开关：

| 变量 | 默认 | 作用 |
|---|---|---|
| `TABLE_STRUCTURE_ENABLED` | false | 是否加载表格检测/结构模型 |
| `TABLE_STRUCTURE_DEVICE` | cpu | `cpu` / `mps` |
| `TABLE_CELL_OCR` | true | 表格单元格逐格 OCR |
| `TABLE_CONFIDENCE` | 0.5 | 低置信度 warning 阈值 |
| `TABLE_TILE_DETECTION` | true | 大图分块补检 |
| `TABLE_DETECTION_MODEL_PATH` | `.models/table-transformer-detection` | 检测模型目录 |
| `TABLE_STRUCTURE_MODEL_PATH` | `.models/table-transformer-structure` | 结构模型目录 |
| `OCR_DESKEW` | false | 扫描页 deskew（实验性） |
| `OCR_MAX_SKEW` | 15 | deskew 最大角度 |

### 2.5 离线环境变量

写入 `scripts/run_web.sh` 或 shell profile：

```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
export HF_HUB_DISABLE_TELEMETRY=1
export TOKENIZERS_PARALLELISM=false
```

作用：

- 禁止运行期联网校验；
- 模型路径错误时快速失败，而不是重试 7 次（3s→110s）。

### 2.6 首次启动

```bash
source .venv/bin/activate
python -m app
# 或
scripts/run_web.sh
```

浏览器打开：<http://127.0.0.1:8765>

首次启动会：

1. 检查 `.models/READY.json` 与权重文件；
2. 打开/创建 `data/lancedb`；
3. 创建 `chunks` 表与 FTS(ICU) 索引；
4. 同步预热两个模型（健康检查通过前完成，约 2–3s，热缓存更快）；
5. 打开 Web UI。

## 4. 备份与恢复

### 4.1 备份

```bash
# 建议先停止服务
mkdir -p ~/Backups/content-search
cp -R data ~/Backups/content-search/data-$(date +%Y%m%d)
```

### 4.2 恢复

```bash
# 停止服务后
rm -rf data
cp -R ~/Backups/content-search/data-YYYYMMDD data
```

### 4.3 只重建清单

若 manifest 损坏但 LanceDB 还在：

```bash
mv data/manifest.sqlite data/manifest.sqlite.bak
# 启动后重新扫描；LanceDB 中已有 chunk 不会自动关联，需要重新同步以修复状态
```

> 不要手工 `rm` LanceDB 里的文件；用 `table.delete()` 或重建。

## 5. 升级与迁移

### 5.1 升级依赖

```bash
source .venv/bin/activate
uv pip install -e ".[dev]" --upgrade
```

**原则：**

- 锁定 `lancedb==0.40.0`；升级前先看 changelog；
- 升级后跑 `tests/test_db.py` 与 `tests/test_search.py`；
- 若 FTS API 变化，重跑 STEP-01 的中文召回冒烟。

### 5.2 换 Embedding 模型

换模型（维度变化）必须重建库：

```bash
# 1. 备份
# 2. 修改 EMBED_MODEL / EMBED_DIM
# 3. 删除 data/lancedb
# 4. 重新同步
```

原因：向量维度与表的 `fixed_size_list` 绑定；不同模型的向量空间不可混用。

### 5.3 换 Reranker

只影响查询，不需要重建库：

```bash
RERANK_MODEL=bge-reranker-base python -m app
```

### 5.4 换 FTS 分词器

`ICU → jieba` 需要重建 FTS 索引：

```python
table.create_index("text", config=FTS(base_tokenizer="jieba/default"), replace=True)
```

同时确认词典已放到 Lance 的语言模型目录。

## 7. 排障手册

### 7.1 启动/模型

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: sentencepiece` | XLM-R tokenizer 需要 | `uv pip install sentencepiece` |
| `MODEL_NOT_READY` | 路径/文件缺失 | 检查 `.models/*/pytorch_model.bin` 大小 |
| 查询卡住数分钟，日志反复 retry | 模型路径失效，HF 退避重试 | 用绝对路径；`max_retries=1`；`HF_HUB_OFFLINE=1` |
| `MPS backend out of memory` | 批次过大/内存不足 | 降 `EMBED_BATCH_SIZE`/`RERANK_BATCH_SIZE`；或 `DEVICE=cpu` |
| 模型加载很慢 | 冷启动/磁盘 | 启动同步预热；首次耐心等待 |
| `Repo id must use alphanumeric...` | 把相对路径当成了 HF repo id | 改为绝对路径 |

### 7.2 检索

| 现象 | 原因 | 处理 |
|---|---|---|
| 中文关键词搜不到 | 用了默认 `simple` 分词 | `base_tokenizer="icu"`，重建 FTS |
| `ValueError: Tantivy-based FTS has been removed` | 残留 `use_tantivy=True` | 删除该参数，重建索引 |
| `Field path 'l2' not found` | `create_index(config=...)` 没传列名 | `create_index("text", config=FTS(...))` |
| 结果全是同一文档 | 未去重 | `PER_DOC_LIMIT=2`；启用 MMR |
| 语义能搜到、关键词不行 | FTS 索引缺失/分词错误 | 检查 `list_indices()`；重建 |
| 向量结果差 | 查询没加 instruction；切片过长 | 加指令前缀；400 字上限 |
| 重排后反而变差 | 候选噪声/切片过长 | 降 top_k；缩短切片；换 base 模型 |

### 7.3 解析

| 现象 | 原因 | 处理 |
|---|---|---|
| PDF 无文本 | 扫描件 | 确认 `OCR_ENABLED=true`；页面文本阈值 |
| OCR 空 | 图片太小/纯色/手写 | 跳过并提示；`ocr_available()` 自检 |
| DOCX 图片没进库 | 图片关系未遍历/太小 | 检查 `document.part.rels`；调 `OCR_MIN_IMAGE_PX` |
| PPTX 备注丢失 | 未读 notes | 确认 `slide.has_notes_slide` |
| 编码乱码 | 非 UTF-8 | 检查 charset-normalizer 结果；手动指定 gb18030 |
| 加密 PDF | 需要密码 | 标记 `ENCRYPTED_PDF`，跳过 |

### 7.4 运行/系统

| 现象 | 原因 | 处理 |
|---|---|---|
| 端口被占用 | 8765 已被用 | 改 `APP_PORT` 或杀掉进程 |
| `database is locked` | 多进程同时写 SQLite | 只跑一个服务；WAL 模式 |
| 磁盘满 | 向量/日志增长 | 清理日志；`optimize()`；删旧文档 |
| 浏览器打不开 | 服务未启动/绑定错误 | 确认监听 `127.0.0.1:8765` |
| 页面 404 | 静态文件未挂载 | 检查 `web/` 与 StaticFiles |

## 8. 安全与隐私检查

- [ ] 服务只监听 `127.0.0.1`，不监听 `0.0.0.0`；
- [ ] 关闭 Wi-Fi 后仍可搜索、入库；
- [ ] `lsof -i -P | grep 8765` 只看到本机回环；
- [ ] 日志中没有正文；
- [ ] `/api/open` 不能打开索引根之外的路径；
- [ ] 前端没有外链 CDN/字体/统计脚本；
- [ ] 没有 `requests` 调用云端（代码审计）。
