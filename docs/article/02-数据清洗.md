# 第 2 章 数据清洗

## 一句话结论

数据清洗不是“把文本洗得干净”，而是：

```text
让进入索引的内容可解析、可追溯、结构不丢、噪声可控。
```

## 2.1 为什么清洗决定上限

一个常见的 RAG 失败链路：

```text
PDF 表格被解析成一行乱码
→ chunk 切碎
→ embedding 学不到结构
→ 检索找不到
→ 生成模型编造
```

模型不是万能的。  
如果证据在入库前就丢了，后面的检索和生成都无法恢复。

## 2.2 文件发现与范围控制

第一步不是解析，而是决定“索引什么”。

需要记录：

```text
路径
大小
mtime
content_hash
文件类型
状态
```

术语：

| 术语 | 解释 |
|---|---|
| Manifest | 文件清单，记录文件状态和版本 |
| doc_id | 文档唯一 ID |
| content_hash | 文件内容哈希，用于判断是否变化 |
| run_id | 一次索引构建的版本 ID |
| mtime | 文件修改时间 |

范围控制：

- 只扫描明确允许的目录；
- 忽略 `.git`、缓存、系统目录；
- 支持 include/exclude；
- 不索引临时文件和超大文件；
- 删除文件时同步删除索引。

> 进阶：动态文档里，mtime 只能作为“候选变化”，最终要用 content_hash 判断内容是否真的变了。

## 2.3 解析：不同格式不能都当纯文本

| 格式 | 必须保留的结构 |
|---|---|
| Markdown | 标题层级、列表、代码块、表格 |
| PDF | 页、段落、表格、扫描页 OCR |
| DOCX | 标题、段落、表格、图片 |
| PPTX | 幻灯片、备注、表格、图表文字 |
| HTML | DOM、标题、正文容器、alt text |
| JSON/CSV | 字段名、记录、类型 |
| 图片 | OCR 文本、bbox、置信度 |

术语：

| 术语 | 解释 |
|---|---|
| Parser | 解析器 |
| Block | 解析后的结构块 |
| OCR | Optical Character Recognition，光学字符识别 |
| bbox | Bounding Box，页面中的矩形坐标 |
| Layout | 版面结构，标题、分栏、页眉、表格位置 |

### 一个最小 block 设计

```text
text        文本
kind        heading/paragraph/table/code/ocr
page        页码
slide       幻灯片页码
heading     所属标题
meta        扩展信息
```

没有结构，chunk 只能按长度硬切，标题和正文会被混在一起。

## 2.4 文本规范化

常见处理：

- 统一 UTF-8；
- 去 BOM、零宽字符；
- 合并 PDF 断行；
- 去重复页眉、页脚、页码；
- 保留标题和列表；
- 不删除“看起来像噪声”的内容。

术语：

| 术语 | 解释 |
|---|---|
| Boilerplate | 模板化重复内容，如页眉页脚 |
| Normalization | 规范化 |
| Deduplication | 去重 |

### 页眉页脚为什么要单独处理

扫描件里，页眉页脚会在每一页重复出现：

```text
公司机密
第 1 页
...
公司机密
第 2 页
```

如果不去除：

- 每个 chunk 都带相同噪声；
- 向量被模板文本稀释；
- 关键词检索被页码干扰。

但也不能“看到重复就删”。  
跨页统计、位置约束、页码模式要一起用。

## 2.5 OCR 与版面

扫描 PDF/图片需要：

```text
OCR 文本
文本行 bbox
置信度
阅读顺序
```

术语：

| 术语 | 解释 |
|---|---|
| OCR Confidence | OCR 置信度 |
| Reading Order | 阅读顺序 |
| Multi-column | 多栏排版 |
| Deskew | 倾斜校正 |

常见问题：

- 多栏被按 y 坐标读成一行；
- 表格线被识别成文字；
- 页眉和正文粘连；
- 倾斜导致行合并；
- 低置信度文本被当成确定内容。

> 进阶：OCR 结果必须保留 bbox。没有 bbox，就无法判断文本属于哪一栏、哪个表格、哪个页眉。

## 2.6 表格清洗

表格不要只拼成一行字符串。

应该保留：

```text
行
列
单元格 bbox
表头
合并单元格（rowspan/colspan）
HTML
置信度
```

术语：

| 术语 | 解释 |
|---|---|
| Table Structure Recognition | 表格结构识别 |
| Cell OCR | 单元格单独 OCR |
| Spanning Cell | 合并单元格 |
| rowspan/colspan | HTML 中跨行/跨列 |

### 内容保留原则

如果表格 OCR 失败：

```text
不能删除原始 OCR 行
不能生成空表冒充成功
```

正确做法：

- 空表 → 保留原文；
- 部分 cell 失败 → 只删除已被完整 cell 覆盖的行；
- 低置信度 → 保留 warning；
- 结构失败 → 显式标记，不静默降级。

## 2.7 元数据与权限

每个 chunk 最好带：

```text
doc_id
chunk_index
file_name
file_path
file_type
page/slide
heading
source_kind
run_id
```

用途：

- 过滤；
- 引用；
- 去重；
- 版本隔离；
- 权限控制。

术语：

| 术语 | 解释 |
|---|---|
| Metadata | 元数据 |
| Scalar Filter | 标量过滤，如按文件类型筛选 |
| Scope | 检索范围 |
| Provenance | 来源追溯 |

## 2.8 清洗的验收标准

不要只看“处理成功”，要看：

- 标题是否保留？
- 表格是否可读？
- 页眉页脚是否去除？
- OCR 低置信度是否可见？
- 失败文件是否有明确错误码？
- 删除文件是否从索引消失？
- 解析结果是否可追溯到原文件/页码？

## 2.9 本项目的经验

已做：

- 十类格式解析；
- OCR 行级 bbox；
- 跨页页眉/页脚统计；
- 多栏阅读顺序；
- 表格结构；
- 单元格 OCR；
- 表格 HTML；
- 解析失败显式记录；
- PDF 子进程隔离。

重要教训：

```text
最危险的不是“没洗干净”，
而是“洗掉了但没人知道”。
```

## 2.10 检查清单

- [ ] 文件范围是否明确？
- [ ] 编码是否统一？
- [ ] 页眉页脚是否处理？
- [ ] 表格是否保留结构？
- [ ] OCR 是否保留 bbox/置信度？
- [ ] 失败是否显式暴露？
- [ ] 元数据是否足够过滤和引用？
- [ ] 删除文件是否清索引？
