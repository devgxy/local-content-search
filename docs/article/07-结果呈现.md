# 第 7 章 检索结果呈现

## 一句话结论

结果呈现不是“把 text 打出来”，而是帮助用户判断：

```text
为什么相关？
出自哪里？
是否可信？
下一步能做什么？
```

## 7.1 结果卡片

一个可用的结果卡片通常包含：

| 元素 | 作用 |
|---|---|
| 文件名/路径 | 来源 |
| 页码/幻灯片 | 定位 |
| 标题/章节 | 上下文 |
| snippet | 命中片段 |
| highlight | 高亮 query 词 |
| summary | 摘要 |
| 缩略图 | 视觉定位 |
| 表格 HTML | 结构化展示 |
| 置信度 | 质量提示 |
| warning | 解析/OCR 问题 |
| 操作按钮 | 预览、打开、复制 |

术语：

| 术语 | 解释 |
|---|---|
| Snippet | 命中片段 |
| Highlight | 高亮 |
| Citation | 引用 |
| Provenance | 来源追溯 |
| Confidence | 置信度 |
| Fallback | 降级方案 |

## 7.2 Chunk-level 与 Doc-level

### Chunk-level

```text
一条结果 = 一个 chunk
```

优点：定位精确。  
缺点：同一文档重复多。

### Doc-level

```text
一条结果 = 一个文档
文档内展示最佳 chunk
```

优点：适合“找文件”。  
缺点：细节定位弱。

术语：

| 术语 | 解释 |
|---|---|
| Chunk-level | 分块级结果 |
| Doc-level | 文档级结果 |
| Grouping | 聚合 |
| Per-doc Cap | 每文档上限 |

## 7.3 引用和证据

RAG 的结果应该能回答：

```text
这句话来自哪份文件、哪一页、哪一段？
```

推荐：

- 文件名；
- 页码/幻灯片；
- 章节；
- 命中片段；
- 原文链接/预览。

如果接 LLM：

```text
答案
[1] 文件名，第 3 页
[2] 文件名，第 7 页
```

原则：

- 关键结论有引用；
- 找不到证据就明说；
- 不把模型记忆当资料；
- 展示检索证据，不只展示最终答案。

术语：

| 术语 | 解释 |
|---|---|
| Grounding | 基于检索证据 |
| Citation Accuracy | 引用是否支持结论 |
| Hallucination | 幻觉 |
| Abstention | 拒答 |

## 7.4 表格和图片

表格不要只显示一行文本：

- 渲染 HTML 表格；
- 显示结构置信度；
- 低置信度标记；
- 保留原图预览。

图片：

- 缩略图；
- OCR 文本；
- 原图打开；
- 页码/区域。

### 安全

表格 HTML 不要直接 `innerHTML` 任意内容。  
应使用白名单 DOM：

```text
只允许 table/tr/th/td
只复制整数 colspan/rowspan
单元格用 textContent
```

## 7.5 空结果和失败

不要只显示“没有结果”。

应该区分：

- 索引为空；
- 过滤过严；
- 查询无匹配；
- 模型不可用；
- 解析失败。

```text
无结果
≠
系统坏了
```

界面要给可操作建议：

- 放宽过滤；
- 换关键词；
- 检查索引；
- 查看 warning。

## 7.6 结果排序的解释

用户会问：

```text
为什么这条排第一？
```

可以展示：

- 命中方式：向量/关键词/混合；
- 分数类型；
- 重排分；
- 命中高亮。

不要展示无法解释的“神秘分数”。
