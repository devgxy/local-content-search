# 第 3 章 Chunk 切片

## 一句话结论

Chunk 不是越小越好：

```text
小 chunk 提高定位精度，但丢上下文；
大 chunk 保留上下文，但向量被稀释。
```

## 3.1 为什么必须切

embedding 模型有最大输入长度。  
整篇文档压成一个向量，细节会被平均掉。

```text
文档 → 多个 chunk → 每个 chunk 一个向量
```

术语：

| 术语 | 解释 |
|---|---|
| Chunk | 文档切片，检索最小单位 |
| Chunk Size | 切片大小，常用字符数或 token 数 |
| Overlap | 相邻 chunk 的重叠部分 |
| Token | 模型分词后的基本单位 |
| Context Window | 模型一次能处理的最大 token 数 |

## 3.2 五种常见策略

### ① 固定长度

```text
每 500 字切一刀，重叠 50 字
```

优点：简单、稳定。  
缺点：切断句子、表格、代码。

### ② 递归切分

按优先级尝试：

```text
段落 → 句子 → 逗号 → 固定长度
```

优点：尽量保持语义完整。

### ③ 结构感知

按标题/段落/列表/表格/代码块切。

优点：保留标题和上下文。  
缺点：依赖解析质量。

### ④ 父子 chunk

```text
小 chunk 用于检索
大 parent 用于返回上下文
```

术语：

| 术语 | 解释 |
|---|---|
| Parent-Child Chunking | 子块检索，父块提供上下文 |
| Small-to-Big | 先命中小块，再扩展到大块 |
| Contextual Retrieval | 给 chunk 补充文档/章节上下文 |

### ⑤ 语义切分

用 embedding 判断句子相似度，在语义转折处切。  
成本高，适合高质量小语料。

## 3.3 参数权衡

| 参数 | 太小 | 太大 |
|---|---|---|
| chunk size | 语义不足、召回碎片化 | 噪声多、向量不聚焦 |
| overlap | 边界丢语义 | 重复结果、索引膨胀 |
| top_k | 召回不足 | 噪声和延迟增加 |

没有通用最优值。  
必须用评测集调，不能凭感觉。

## 3.4 特殊内容怎么切

### 表格

表格应独立成块，并保留：

```text
表头
行列结构
HTML
单元格文本
```

不要把一个表格切成“上半张表”和“下半张表”。

### 代码

按函数/类/代码块切，保留语言和文件路径。

### 问答对

一个 QA 对尽量不拆开：

```text
问题 + 答案
```

### 列表

短列表可以合并；长列表按条目切，并保留父标题。

## 3.5 本项目的选择

- 目标约 400 字符；
- overlap 50；
- 最大 600；
- 按标题/段落/表格/代码结构切；
- 表格独立成块；
- 默认不做短上下文拼接，因为 A/B 为负；
- 支持 parent context 重排，但默认关闭。

术语：

| 术语 | 解释 |
|---|---|
| Adaptive Chunking | 自适应切片，按内容调整大小 |
| Parent Context | 父级上下文 |
| A/B | 对照实验 |

## 3.6 Chunk 质量的验收

不要只看 chunk 数量。看：

- 标题是否跟着正文？
- 表格是否完整？
- 代码是否被切断？
- 相邻 chunk 是否重复过多？
- 关键答案是否落在某个 chunk 内？
- chunk-level 指标是否稳定？

## 3.7 检查清单

- [ ] chunk 边界是否尽量落在语义边界？
- [ ] 表格/代码是否特殊处理？
- [ ] overlap 是否造成大量重复？
- [ ] 是否保留标题和页码？
- [ ] 是否用评测验证过参数？
