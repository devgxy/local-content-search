# 第 8 章 评价指标

## 一句话结论

没有评测集的 RAG，只能靠感觉调参。

```text
先定义“什么算对”，再谈“变好了没有”。
```

## 8.1 先定义标签

常见标签：

| 标签 | 含义 |
|---|---|
| relevant | 相关文档路径 |
| relevant_chunks | 相关 chunk：`path#chunk_index` |
| relevant_anchors | 内容锚点：path + quote + doc_hash |
| qrels | Query Relevance judgments，查询-相关性标注 |
| ground truth | 人工标注的标准答案 |

评价前必须固定：

```text
语料快照
query 集
标签
模型版本
参数
```

否则数字不可比。

## 8.2 检索指标

### Recall@K

```text
Recall@K = 前 K 条中相关结果数 / 全部相关结果数
```

解释：该找回来的，找回来多少。

适合：召回阶段、不能漏资料的场景。

### Precision@K

```text
Precision@K = 前 K 条中相关结果数 / K
```

解释：返回的结果里，有多少是相关的。

### Hit Rate@K

```text
Hit Rate@K = 至少命中一个相关结果的 query 数 / 总 query 数
```

解释：有多少 query 至少能找到一条对的。

### MRR@K

MRR = Mean Reciprocal Rank。

单条 query：

```text
RR = 1 / 第一个相关结果的排名
```

前 K 没有相关结果：

```text
RR = 0
```

多条 query：

```text
MRR@K = 所有 query 的 RR 平均值
```

例子：

```text
第 1 名相关 → RR = 1
第 2 名相关 → RR = 0.5
第 4 名相关 → RR = 0.25
```

解释：第一个正确结果出现得有多靠前。

### nDCG@K

nDCG = normalized Discounted Cumulative Gain。

```text
DCG@K = Σ (2^rel_i - 1) / log2(i + 1)
nDCG@K = DCG@K / IDCG@K
```

- `rel_i`：第 i 条的相关性等级；
- 二值标注时，相关=1，不相关=0；
- 排名越靠后，折扣越大；
- IDCG 是理想排序的 DCG。

解释：不仅看有没有相关，还看相关结果排得靠不靠前。

### MAP@K

MAP = Mean Average Precision。

```text
AP = Σ (Precision@i × 第 i 条是否相关) / 相关结果总数
MAP = 所有 query 的 AP 平均值
```

解释：相关结果是否整体排在前面。

### F1@K

```text
F1@K = 2 × Precision@K × Recall@K / (Precision@K + Recall@K)
```

解释：Precision 和 Recall 的调和平均。

### 缩写速查

| 缩写 | 全称 | 中文 |
|---|---|---|
| R@K | Recall at K | 前 K 召回率 |
| P@K | Precision at K | 前 K 精确率 |
| MRR | Mean Reciprocal Rank | 平均倒数排名 |
| nDCG | normalized Discounted Cumulative Gain | 归一化折损累计增益 |
| MAP | Mean Average Precision | 平均精确率均值 |
| HR | Hit Rate | 命中率 |
| p50 | 50th percentile | 50% 请求低于该延迟 |
| p95 | 95th percentile | 95% 请求低于该延迟 |
| QPS | Queries Per Second | 每秒查询数 |

## 8.3 chunk-level vs doc-level

```text
doc-level：整个文件算一个单位
chunk-level：具体片段算一个单位
```

风险：

- doc-level 容易“文件对了但段落不对”；
- chunk-level 更严格，但受切片影响；
- 两者不能混着比较。

## 8.4 RAG 生成指标

如果接 LLM：

| 指标 | 含义 |
|---|---|
| Faithfulness | 答案是否忠于检索证据 |
| Answer Relevance | 答案是否回答问题 |
| Context Precision | 上下文中相关证据比例 |
| Context Recall | 所需证据是否检索到 |
| Groundedness | 答案是否有证据支撑 |
| Citation Accuracy | 引用是否支持结论 |
| Hallucination Rate | 幻觉比例 |
| Abstention Rate | 证据不足时拒答比例 |

术语：

| 术语 | 解释 |
|---|---|
| Grounding | 基于证据 |
| Hallucination | 幻觉，模型编造 |
| Abstention | 拒答 |

注意：LLM-as-judge 也有偏差，要人工抽检。

## 8.6 评测协议

```text
1. 固定语料快照
2. 固定 query 集
3. 固定 qrels
4. 固定模型/参数
5. 跑多配置对比
6. 记录 p50/p95
7. 分桶分析
8. 保存失败案例
9. 改动后回归
```

术语：

| 术语 | 解释 |
|---|---|
| Benchmark | 基准评测 |
| A/B Test | 对照实验 |
| Holdout Set | 留出集 |
| Regression | 回归 |
| Bucketing | 分桶 |
| Confidence Interval | 置信区间 |
| Data Leakage | 数据泄漏 |

## 8.7 本项目的指标示例

38 条简历 scoped，911 chunks：

| 配置 | Recall@5 | Recall@10 | MRR | nDCG | p50 |
|---|---:|---:|---:|---:|---:|
| hybrid | 0.6561 | 0.9518 | 0.6509 | 0.6974 | 30ms |
| full | 0.5684 | 0.9671 | 0.5349 | 0.6481 | 388ms |

解释：

- hybrid 更适合 scoped；
- full 的 rerank 不稳定；
- auto 在 scoped 下用 hybrid。

必须注明：

```text
38 条是小样本，只能看趋势；
不能把 0.01 的差异当统计显著。
```
