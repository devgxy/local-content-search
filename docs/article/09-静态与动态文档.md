# 第 9 章 静态文档 vs 动态文档

## 一句话结论

静态/动态不是文件格式差异，而是**文档生命周期差异**。

```text
静态：一次性、稳定、可快照
动态：持续变化、要增量、要版本、要删除
```

## 9.1 两类文档

### 静态文档

典型场景：

- 产品手册；
- 法规汇编；
- 已归档的报告；
- 一次性交付的资料。

特点：

```text
内容稳定
一次建库
批量重建
查询为主
```

### 动态文档

典型场景：

- 个人文件目录；
- 企业知识库；
- Wiki；
- 简历库；
- 合同/财报模板；
- 数据库/消息流。

特点：

```text
新增、修改、删除
权限变化
需要增量
需要版本
需要清理
```

## 9.2 三类“动态”

不要把动态文档只理解成“文件会变”。

### ① 内容动态

文件新增/修改/删除。

关键：

```text
mtime 候选
content_hash 确认
run_id 版本隔离
tombstone 删除
```

### ② 结构动态

模板、表格、字段变化：

- 合同字段；
- 财报表格；
- 简历模板；
- 表单。

关键：

```text
不能只按纯文本切；
要保留字段名、表格行列、单元格语义。
```

### ③ 实时动态

数据库、消息、API：

- 不能全量重建；
- 需要增量同步；
- 需要过期数据清理；
- 需要权限和时序。

## 9.3 核心差异表

| 维度 | 静态文档 | 动态文档 |
|---|---|---|
| 语料变化 | 一次性、稳定 | 持续新增/修改/删除 |
| 索引方式 | 批量全量重建 | 增量扫描 |
| 文档 ID | 路径或内容 hash | 路径 + hash + run_id |
| 删除 | 重建即可 | tombstone / 清旧 chunk |
| 一致性 | 快照 | 原子切换、版本隔离 |
| 权限 | 通常统一 | 按文件/目录/用户过滤 |
| 评测 | 固定快照 | 按版本快照评测 |
| 成本 | 低 | 扫描、去重、回滚、清理成本高 |
| 失败影响 | 单次重建 | 可能新旧索引混杂 |

## 9.4 动态文档的索引生命周期

```text
扫描
→ 判断变化
→ 解析
→ 切片
→ 向量化
→ 写入新 run
→ 切换 manifest
→ 清理旧 run
```

每一步都可能失败：

- 扫描失败：文件漏掉；
- 解析失败：单文件坏；
- 切片失败：内容不完整；
- 写入失败：新旧混杂；
- 切换失败：半成品可见；
- 清理失败：重复结果。

### 关键原则

```text
先写新版本
→ 成功后再切换
→ 最后清理旧版本
```

不要先删除旧版本再写新版本。

术语：

| 术语 | 解释 |
|---|---|
| Atomic Switch | 原子切换 |
| Run | 一次索引构建 |
| Tombstone | 删除标记 |
| Rollback | 回滚 |
| Stale Chunk | 过期 chunk |

## 9.5 文档 ID 和版本

静态文档可以简单：

```text
doc_id = hash(path)
```

动态文档建议：

```text
doc_id    稳定标识文档
run_id    标识本次构建
chunk_id  run_id + doc_id + chunk_index
```

为什么：

- 同名文件可能被替换；
- 同一路径内容可能变化；
- 旧 chunk 不能和新 chunk 混在一起；
- 删除/回滚需要定位版本。

## 9.6 删除比新增更难

新增：

```text
写入新 chunk
```

删除：

```text
标记文件删除
→ 从检索中排除
→ 清 chunk
→ 清图片资产
→ 清 manifest
```

如果只删 manifest，不删 chunk：

- 搜索仍可能命中已删除文件；
- 旧内容泄露；
- 结果重复。

如果只删 chunk，不删 manifest：

- 扫描状态不一致；
- 下次可能重复处理。

## 9.7 权限与 scope

静态库通常权限统一。

动态库常见：

```text
不同目录不同权限
不同用户不同可见范围
```

检索必须先过滤再召回：

```text
prefilter
```

术语：

| 术语 | 解释 |
|---|---|
| Prefilter | 先按元数据过滤，再向量检索 |
| Postfilter | 先检索，再过滤 |
| ACL | Access Control List，访问控制列表 |

先检索再过滤的风险：

- 过滤后结果不足；
- 泄露不该看到的候选；
- 分页/计数不准。

## 9.8 评测差异

静态文档：

```text
固定快照
一次评测
```

动态文档：

```text
每次索引构建生成快照
按 run_id 评测
旧版本可回放
```

否则：

```text
今天和昨天的指标不可比
```

## 9.9 本项目的实现

当前项目是文件系统型动态文档：

- Manifest 记录文件状态；
- mtime + hash 判断变化；
- run_id 隔离版本；
- 新版本写成功后才切换；
- 删除文件清理旧 chunk；
- scope 支持文件/目录过滤；
- `auto` 在 scoped 下用 hybrid。

表格/简历等文档还带有“结构动态”：

- 表格行列变化；
- 合并单元格；
- 字段位置变化；
- 扫描件 OCR 噪声。

所以不能只按纯文本处理。

## 9.10 常见坑

1. 只用 mtime 判断变化：时间变了，内容没变，白重建。
2. 先删旧数据再写新数据：中途失败，索引空了。
3. 新旧 run 同时可搜索：结果重复/串版本。
4. 删除文件只删 manifest：旧 chunk 仍可被检索。
5. 先检索再权限过滤：可能泄露候选。
6. 评测不绑定快照：指标不可比。

- [ ] 是否有 content_hash？
- [ ] 是否有 run_id？
- [ ] 是否原子切换？
- [ ] 删除是否清 chunk/asset？
- [ ] 权限是否 prefilter？
- [ ] 评测是否绑定快照？
