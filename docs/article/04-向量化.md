# 第 4 章 向量化

## 一句话结论

Embedding 把文本变成向量，让“语义相近”变成“距离更近”。

```text
文本 → 模型 → 固定维度向量
```

但它不是魔法：模型、指令、维度、截断、版本都会影响结果。

## 4.1 向量是什么

```text
"无障碍节点采集" → [0.12, -0.03, ..., 0.44]
```

向量维度常见：

```text
384 / 768 / 1024 / 1536 / 3072
```

本项目使用：

```text
bge-large-zh-v1.5
1024 维
```

术语：

| 术语 | 解释 |
|---|---|
| Dense Vector | 稠密向量，每个维度都有值 |
| Sparse Vector | 稀疏向量，大部分维度为 0 |
| Dimension | 向量维度 |
| Cosine Similarity | 余弦相似度，看方向夹角 |
| Inner Product | 内积，向量点积 |
| Normalization | 归一化，把向量长度变成 1 |
| ANN | Approximate Nearest Neighbor，近似最近邻 |

## 4.2 相似度怎么算

余弦相似度：

```text
cos(a, b) = (a · b) / (|a| × |b|)
```

如果向量已经归一化：

```text
cos(a, b) = a · b
```

很多向量库用内积/IP 或 cosine，取决于索引配置。

## 4.3 Dense 和 Sparse

### Dense

- 每个维度都有值；
- 擅长语义相似；
- 对同义词、改写更稳。

### Sparse

- 大部分维度为 0；
- 擅长精确词、编号、专有名词；
- BM25 是典型代表。

```text
Dense：意思相近
Sparse：字面命中
```

混合检索就是两者互补。

## 4.4 Bi-Encoder 和 Cross-Encoder

| 类型 | 输入 | 特点 |
|---|---|---|
| Bi-Encoder | query 和 doc 分别编码 | 快，适合召回 |
| Cross-Encoder | query + doc 一起输入 | 准，适合重排 |

```text
Bi-Encoder：先编码，后算距离
Cross-Encoder：直接判断这一对有多相关
```

术语：

| 术语 | 解释 |
|---|---|
| Encoder | 编码器 |
| Reranker | 重排模型 |
| Recall Stage | 召回阶段 |
| Rerank Stage | 重排阶段 |

## 4.5 Query / Passage 指令

很多模型要求不同前缀：

```text
query: 为这个句子生成表示以用于检索...
passage: ...
```

术语：

| 术语 | 解释 |
|---|---|
| Query Instruction | 查询侧指令 |
| Passage Prefix | 文档侧前缀 |
| Asymmetric Retrieval | 查询和文档编码方式不同 |

用错前缀会明显掉点。  
具体前缀必须以模型卡为准，不能照抄别的模型。

## 4.6 工程参数

### 维度

- 存储成本；
- 检索速度；
- 模型能力。

维度不是越高越好，要和模型匹配。

### 归一化

归一化后：

- cosine 等价于内积；
- 距离更稳定；
- 索引配置要一致。

### Batch

批量编码提高吞吐，但要注意内存。

### 截断

模型有最大 token 长度。  
超长文本会被截断，尾部信息丢失。

术语：

| 术语 | 解释 |
|---|---|
| Batch Size | 批大小 |
| Truncation | 截断 |
| Max Sequence Length | 最大序列长度 |
| MPS | Apple Metal Performance Shaders，Mac GPU 加速 |

## 4.7 模型版本与索引版本绑定

换 embedding 模型意味着：

```text
向量空间变了
旧库不能直接混用
必须重建索引
```

术语：

| 术语 | 解释 |
|---|---|
| Embedding Drift | 换模型/版本后向量空间变化 |
| Reindex | 重建索引 |
| Model Version | 模型版本 |

本项目在 schema 中记录模型/维度信息，维度不匹配直接报错，不静默混用。

## 4.8 什么时候需要微调

可以先不微调。  
优先检查：

1. 数据清洗；
2. chunk；
3. query 指令；
4. 混合检索；
5. 重排。

这些都比微调便宜。

需要微调的信号：

- 领域词很多，通用模型完全不理解；
- 有大量高质量 query-doc 对；
- 业务指标明确，且清洗/chunk 已稳定。

## 4.9 检查清单

- [ ] 模型和维度是否固定？
- [ ] query/passage 指令是否正确？
- [ ] 是否归一化？
- [ ] 截断长度是否合理？
- [ ] 模型版本是否和索引绑定？
- [ ] 是否测过无模型/模型缺失的显式错误？
