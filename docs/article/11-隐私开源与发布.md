# 第 11 章 隐私、开源与发布

## 一句话结论

公开代码前，先假设：

```text
所有路径、姓名、邮箱、电话、截图都可能被看到。
```

脱敏不是“改个 README”，而是对整个仓库做审计。

## 11.1 常见泄露点

- 绝对路径：`/Users/<name>/...`
- 真实姓名、手机号、邮箱；
- 公司/学校/薪资；
- 简历、合同、客户资料；
- 截图中的文件名；
- `.env`、token、AppSecret；
- Git 历史里的旧提交；
- 数据集/模型许可证。

## 11.2 公开前检查

### 文件

```text
data/
.models/
.venv/
tests/fixtures/
reports/ 原始数据
.idea/
.env
*.log
```

### 文本

搜索：

```text
/Users/
/home/
1[3-9][0-9]{9}
@
真实姓名
公司名
```

### Git 历史

只在最新 commit 删除不够。  
如果历史里有敏感文件：

```bash
git filter-repo --path <敏感文件> --invert-paths
```

或使用 BFG。  
然后 force push，并清理缓存。

### Token

- 不提交 `.env`；
- 不把 PAT 发聊天；
- 泄露后立即撤销；
- 使用最小权限、短期 token。

## 11.3 公开仓库结构

建议：

```text
README.md
LICENSE
app/
tests/
docs/
scripts/
examples/      # 脱敏小样例
reports/       # 脱敏验收摘要
```

不要放：

```text
用户原始文档
模型权重
数据库
日志
个人评测集
```

## 11.4 数据集与模型许可证

- 模型权重只给下载方式，不随仓库分发；
- 公开数据集只引用来源；
- 核对许可证是否允许再分发；
- 不把 Kaggle/HuggingFace 数据直接打包进仓库。

## 11.5 GitHub 发布

推荐顺序：

```text
1. 本地脱敏
2. private 仓库验证
3. 检查远端文件列表
4. 改为 public
5. 再发布文章
```

公开后检查：

- 文件树；
- 历史 commit；
- README 链接；
- 是否有 token；
- 是否有个人路径。

## 11.6 CSDN 与微信公众号

### 推荐顺序

```text
GitHub 代码 public
→ 微信原创首发
→ CSDN 同步
→ GitHub 归档文章
```

原因：

- 微信“原创”更看重首发；
- CSDN 先发后，微信可能判定重复；
- CSDN 适合搜索流量，晚发不影响。

### 微信

- 不支持直接 Markdown；
- 用 md2wechat/Doocs/135 转换；
- 代码块、表格、公式要转图片或重新排版；
- 外链不可点击，GitHub 链接放“阅读原文”；
- 长文拆系列。

### CSDN

- 支持 Markdown；
- 保留完整代码和公式；
- 图片上传到 CSDN；
- 文末放 GitHub 链接；
- 标注首发信息。

### 公众号 API（可选）

需要：

- 已认证账号；
- 草稿/发布/素材接口权限；
- AppID/AppSecret；
- IP 白名单。

没有权限就手动发文，不要花时间配 API。

## 11.7 发布前检查清单

- [ ] 无真实姓名/电话/邮箱？
- [ ] 无绝对路径？
- [ ] 无 `.env`/token？
- [ ] 无原始用户数据？
- [ ] Git 历史干净？
- [ ] 数据集/模型许可证明确？
- [ ] README 能按步骤跑通？
- [ ] 文章链接有效？
- [ ] 微信/CSDN 首发策略确定？

## 11.8 最后一句

```text
开源不是把本地目录直接推上去，
而是把“可复现的代码”和“不可公开的数据”分开。
```
