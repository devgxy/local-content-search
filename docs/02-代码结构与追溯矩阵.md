## 5. 文件状态机（manifest.files.status）

```text
pending ──parse/embed OK──> indexed
   │                           │
   │ parse/embed fail          │ 文件变更（size/mtime/hash）
   ▼                           ▼
 error <──fail────────────── reindex（仍显示 indexed，直到成功）
   │
   └── 用户删除 ──> deleted（LanceDB 清理后）
```

约束：

- `indexed` 才允许出现在搜索结果的正常状态；
- `error` 保留旧 chunk，但 UI 用黄色标记“索引失败”；
- `deleted` 的 chunk 必须已从 LanceDB 删除；若未删干净，启动恢复；
- `pending` 只出现在扫描后发现、尚未同步的文件。

### 6.2 文档侧

每个 STEP 文档必须包含“代码映射”表：

| 文件 | 符号 | 说明 | 测试 |

### 6.3 测试命名

- 单元：`tests/test_<module>.py::test_<behavior>`
- 集成：`tests/test_ingest.py::test_end_to_end_mixed_formats`
- 手工验收：STEP 文档给出命令 + 期望输出。

### 6.4 变更流程

1. 先改 DOC-00（数据/API/配置）；
2. 再改对应 STEP 文档；
3. 再改代码与测试；
4. 最后更新 DOC-02 的映射表与状态。

## 8. 错误码与归属

| 错误码 | 触发 | 处理 | 归属 |
|---|---|---|---|
| `MODEL_NOT_READY` | 模型目录缺失/加载失败 | 启动自检失败；API 503 | STEP-02 |
| `DB_NOT_READY` | LanceDB 打不开/迁移失败 | 启动失败；提示路径 | STEP-01 |
| `DB_SCHEMA_MISMATCH` | 维度/模型与库不一致 | 拒绝启动；提示重建 | STEP-01 |
| `FTS_NOT_READY` | FTS 索引缺失 | 自动重建；失败则报错 | STEP-01 |
| `INVALID_QUERY` | 空 query/超长 | 400 | STEP-07 |
| `INVALID_PATH` | 路径越界/不存在 | 400 | STEP-08 |
| `FILE_TOO_LARGE` | > 200MB | 跳过并记录 | STEP-06 |
| `PARSE_FAILED` | 解析异常 | 文件级错误，继续其他文件 | STEP-03 |
| `EMPTY_DOCUMENT` | 解析/OCR 后无文本 | 标记 error，跳过 | STEP-06 |
| `ENCRYPTED_PDF` | 加密且空密码失败 | 跳过并提示 | STEP-03 |
| `INTERRUPTED` | 入库进程中断 | 启动恢复为 error，等待重试 | STEP-06 |
| `BUSY` | 已有同步任务 | 409 | STEP-06 |
| `JOB_NOT_FOUND` | job_id 无效 | 404 | STEP-06 |
| `RERANK_FAILED` | 重排失败 | 显式失败，不降级 | STEP-07 |
